# 技术基线

> 选型与理由，供后来者判断「能不能换」。产品的设计约束见 `../smart-wine-cooler-wiki/`。

---

## 1. 运行形态

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 运行形态 | **单进程 + 线程** | 局域网并发极少；NPU 推理是 C 调用会释放 GIL，线程能真并行；状态天然一致 |
| 推理位置 | **独立线程**，绝不跑在事件循环里 | 一次观察要跑好几秒，跑在循环里界面会全程无响应 |
| 前后端通知 | **前端→后端 HTTP；后端→前端 SSE** | 只有「后端主动开口」这一件事需要长连接。单向推送用 SSE 就够，不必上 WebSocket：这里前端没有需要推给后端的东西，却要额外养心跳与重连 |
| 长动作 | **受理即返回，结果靠事件通知** | 观察、维护这类要跑几秒的动作不占着请求；否则请求一断，界面上写着失败、后端却已经做完 |
| 关停 | **收到 SIGTERM/SIGINT 先收 SSE 流，再退出** | uvicorn 退出时会等连接自然关闭，而 SSE 永不结束——不收掉就只能等 systemd 超时 SIGKILL（默认 90 秒）。`main.py` 用 `Server` 子类在 `handle_exit` 里先 drain 总线；unit 里 `TimeoutStopSec=20` 兑底 |
| HTTP | **FastAPI + uvicorn** | 异步、自带校验；能输出 OpenAPI，前端类型由它生成 |
| 接口契约 | **后端手写，前端类型自动生成** | 一份定义只写一次。反方向做不到——TypeScript 类型只描述数据形状，不描述端点 |
| 数据库 | **SQLite + WAL**，标准库 `sqlite3`，不用 ORM | 单文件、有事务、无服务进程；表结构简单，直写 SQL 更可控 |
| 图像 | `Pillow` + `numpy` | 板端没有 OpenCV，几何变换全部用 numpy 自己算 |
| 推理 | 板端 `rknnlite` / 宿主机 `onnxruntime` | 两层适配，接口一致 |
| 前端 | 独立子仓库，**只在宿主机构建** | 板子内存不够跑构建 |
| 配网 | 交给系统层（`nmcli`） | 不自实现无线协议栈，见 `../smart-wine-cooler-wiki/SET §7` |

依赖一律写进各自的 `requirements.txt`，**版本号不写在这里**——它们会随升级变化。

---

## 2. 每个线程一条数据库连接

一条连接给两个线程同时用时，取回来的行会和列名串位，报出来却是 `IndexError` / `JSONDecodeError` 这种跟数据库看不出关系的错。

**所以：连接按线程持有，不共享、不池化。**

---

## 3. 契约的单一真相源

```
后端 pydantic 模型（手写）
        ↓ 导出
    openapi.json
        ↓ openapi-typescript
前端生成类型
```

前端**不手写数据结构的镜像**。`ports.ts` 这类业务抽象层保留，但里面的类型一律引用生成结果，它的职责只剩「方法名 → 业务流程」。

**生成流程必须在部署脚本里有固定位置**，否则会出现「后端改了、前端还在用旧类型」的静默错配。

---

## 4. 路由风格

资源放路径，动作放方法，不把动作塞进路径：`/categories/{id}` + `DELETE`，而不是 `/categories/delete`。

---

## 5. 环境与依赖

两个虚拟环境，别混：

| 环境 | 装什么 | 谁在用 |
| --- | --- | --- |
| `server/.venv` | `server/requirements-host.txt` + `-dev.txt` | 服务端运行与测试、`tools/check`、`tools/deploy`、`tools/gate` |
| `tools/.venv` | `tools/requirements.txt`（汇总各命令清单） | 模型转换、实验、标注 |

- **板端不在这两个里面**：用系统 python + `server/requirements-board.txt`，装到 `~/.local`
- **为什么 tools 共用一个 venv**：转换要 torch、回归要 rknn、实验要 onnx/opencv，都上 GB 且版本一致，按命令拆只是重复装几份；要管的是「依赖写在哪」——`tools/<命令>/requirements.txt`
- **`gate` 用 `server/.venv`**：它跑的是服务端代码，比对的必须是真实运行环境
- **清单分工**：`requirements*.txt` 是要装什么（意图），`*-lock.txt` 是实测快照（`pip freeze`）；复现环境装 lock
