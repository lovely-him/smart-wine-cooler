## 1. 三个入口

| 入口 | 命令 | 干什么 |
| --- | --- | --- |
| 服务 | `python3 -m server.main` | 解析监听地址端口 → 交给 uvicorn 起 FastAPI |
| 契约 | `python3 -m server.openapi` | 导出 `openapi.json`，前端据此生成类型 |
| 前端 | 子仓库里 `npm run build` | 产物被服务当静态文件托管 |

**启动顺序**（`server/main.py` → `server/app.py`）：

```
命令行参数 > 环境变量 > 约定位置     ← 监听地址、端口、库文件、图片目录走这条链
        ↓
bootstrap 配置项（没有就用出厂值）
        ↓
Database（每个线程一条连接）
        ↓
app.py 直接 new 出库、配置、模型、硬件、观察器、调度器
        ↓
build_router / build_preview_router → FastAPI app
        ↓
Scheduler 起后台线程，开始盯门磁与定时
        ↓
main.py 用 Server 子类跑 uvicorn（收到 SIGTERM 先把 SSE 流收掉，再退出）
```

**为什么端口不存数据库**：数据库一坏服务就永远起不来。所以引导信息全在库外。

## 2. 每个包一句话

| 包 | 管什么 |
| --- | --- |
| `server/main.py` `app.py` | 入口与装配：把真实现塞给 service，唯一该 `new` 东西的地方 |
| `server/kernel/` | 内核：`objects.py` 接口形状的唯一手写真相源、`fields.py` 默认字段表、`errors.py` 业务错误、`ordering.py` 位置次序；不许 import 其他模块 |
| `server/platform/` | 基础设施：`db/`（SQLite 与仓储）、`events.py`、`logs.py`、`retention.py`、`storage.py`、`network.py`、门磁与灯（`door`/`light`/`gpio`/`hardware`）、`housekeeping.py`、`status.py`、交付形状 `views.py`，以及引导与参数 `bootstrap` / `layers` / `settings_def` |
| `server/vision/` | 采集与识别：`camera` / `image_dir` / `factory` / `devices`、`stability`、`lens` / `calibrate` / `quality`、`detector` / `embedder` / `classifier` / `features` / `postproc` / `recognize`，以及采集参数 `plan.py`、推理组件 `engines.py`、可用性探测 `probe.py` |
| `server/settings/` | 配置读写与重建：`store.py`（含口令）、`service.py`、`applier.py`、`maintenance.py`（重启/导出） |
| `server/catalog/` | 类别、字段、参考库、AI 补全（`advisor.py`）、未识别分组（`grouping.py`） |
| `server/observe/` | 观察：`runner.py`（一次观察的编排与状态机）、`scheduler.py`（触发调度）、`scan.py`、`layer.py`（单层采集）、`service.py`（观察接口） |
| `server/checkpoint/` | `commit.py`（落的流程）、`service.py`、`queries.py`（历史查询与删除） |
| `server/api/` | HTTP 边界：按资源分文件（snapshot / history / observe / checkpoint / catalog / settings / events / media / preview），不查库 |
| `server/api/schemas.py` | 写操作的请求形状（只放「进得来」的） |
| `server/openapi.py` | 契约导出入口：把 `kernel/objects.py` 导成 `openapi.json` |

## 3. 一次观察怎么走（代码视角）

```
Scheduler（后台线程）
   ↓ 门磁关上 / 定时到点 / 人工触发
observe.runner.ObserveRunner.start_observe()
   ↓ 抢一个「正在观察」的标记，起线程，顺手点灯
observe.scan.run_scan(db, image_dir, plan, engines, housekeeping, trigger, cancel)
   ↓ 开头等光照（cam.warmup）
   ↓ 逐层串行
observe.layer.observe_layer()
   ├─ vision.camera 开流抓一包帧
   ├─ vision.stability 判静止，取出窗口中点那一帧
   ├─ vision.lens 旋转 → 去畸变（只对交出去的那一帧做）
   ├─ vision.detector 检出框
   └─ vision.classifier 逐件归类，认不出的记为未识别
   ↓ 全层成功？
platform.db 落库（观察 + 层记录 + 实体）
   ↓
变化记录（对比核对状态，需要时写一条）
   ↓
EventBus（platform/events.py）→ SSE 通知前端「该刷新了」
```

失败路径：任一层失败 → 整次作废，但**作废照样落库**，界面据失败原因告诉人「这次没拍成，显示的仍是上一次」。

## 4. 一次确认怎么走

```
POST /api/checkpoints
   ↓
api/checkpoint.py               只解析请求
   ↓
checkpoint/service.py           提交器：判冲突、算新版本
   ↓
checkpoint/commit.py            真正的落库流程
   ├─ platform/db/checkpoints   写新的核对状态
   ├─ vision/classifier         参考图入库（差异够大才入）
   └─ 清草稿
```

编辑草稿本身**不在后端**：它是界面上的临时状态（见 wiki `TM §3.8`），后端只在提交时看到最终结果。

## 5. 界面拿数据的两条路

| 路 | 接口 | 特点 |
| --- | --- | --- |
| 快照 | `GET /api/snapshot` | 一份完整当前状态；要小，界面每次刷新都拉 |
| 事件 | `GET /api/events`（SSE） | 只推「该刷新了」，不推数据。数据永远回快照取 |

历史与设置两页「打开才拉」，不靠推送。

## 6. 建议阅读顺序

给第一次读这份代码的人（也给我自己下次回来）：

| 步 | 读什么 | 读完应该知道 |
| :---: | --- | --- |
| 1 | wiki 的 `Home` → `OBS` | 产品在干什么，别急着看代码 |
| 2 | `server/main.py`、`server/app.py` | 服务怎么起来、装了哪些东西 |
| 3 | `server/kernel/objects.py` | 数据长什么样（这是全系统通用语言） |
| 4 | `server/api/` 里挑三个文件（如 `snapshot.py`、`catalog.py`） | 界面怎么把数据要走；接口层薄不薄 |
| 5 | 各模块的 `service.py`（`observe` / `checkpoint` / `catalog` / `settings`） | 一个业务动作从接口接到之后干什么 |
| 6 | `observe/scan.py` → `observe/layer.py` | 一次观察的主干 |
| 7 | `vision/stability.py`、`vision/lens.py` | 「判静止」和「几何纠正」怎么算 |
| 8 | `vision/detector.py`、`vision/classifier.py` | 模型怎么被包成可替换的边界 |
| 9 | `platform/db/__init__.py` 与同目录各仓储 | 为什么每个线程一条连接 |
| 10 | `app.py` | 所有东西是怎么被串起来的（唯一该 `new` 的实现） |

## 7. Python / Linux 概念对照

第一次用 Python 写 Linux 程序时最容易卡住的地方：

| 概念 | 在这里长什么样 |
| --- | --- |
| **包** | 目录 + `__init__.py`；`from server.db import repo` 是绝对导入 |
| **虚拟环境** | `server/.venv/`，用 `server/.venv/bin/python` 跑，不污染系统 Python；工具链另有 `tools/.venv` |
| **模块入口** | `if __name__ == "__main__": sys.exit(main())`；`python3 -m server.openapi` 走这条 |
| **ASGI 服务** | uvicorn 加载 `server.main:app`；异步函数里**不要**做几秒的阻塞操作 |
| **线程** | 观察、调度跑在独立线程；SQLite 连接必须每线程一条，否则行与列名会串位 |
| **日志** | `logging` 进 journald；`server/logs.py` 另留一份内存副本给界面看 |
| **信号 / 退出** | 维护动作「先给响应再退出进程」，否则请求会被一起断掉 |
| **配置文件** | 业务配置进数据库；端口、路径这类引导信息走命令行/环境变量 |
